# 菜市場比價 — 需求規格書（v1.0）

> 交接文件。搭配 `docs/HANDOVER.md`（工程交接注意事項）與根目錄 `README.md`（部署說明）閱讀。

## 1. 背景與目標

發起人平常會去傳統市場買菜買水果，但對價格與產季沒有概念。需要一個**在菜市場現場、用手機、幾秒內**就能回答「這個價格可不可以買」的工具。

核心設計原則：**操作門檻降到最低**。目標使用流程為三步：找到品項 → 輸入看到的價格 → 得到判斷（俗／合理／偏貴）。

## 2. 使用者故事

1. 我站在菜攤前，看到高麗菜一顆 50 元，想馬上知道這算便宜還是貴。
2. 我想知道現在這個月什麼菜/水果/魚是當季盛產，優先買那些。
3. 攤販報價單位不一定是台斤——可能是一顆、一把、一條、一片（鮭魚）、一尾（吳郭魚），工具要能直接用攤販的報價單位判斷。
4. 我希望基準價是真實行情且會定期更新，不是寫死的數字；也要能手動觸發更新。

## 3. 功能需求

### 3.1 品項瀏覽與搜尋
- 分類：葉菜、瓜果茄豆、根莖蔥蒜、菇菌、水果、海鮮、肉類（共約 90 項，清單見 `index.html` 的 `DB`）
- 關鍵字搜尋，支援俗名/別名（例：甘藍=高麗菜、蕹菜=空心菜、吳郭魚=台灣鯛）
- 當季品項排序置前並標「旺」；全年供應品項（菇類、養殖魚、肉類）標「全年供應」

### 3.2 產季資訊
- 每品項有盛產月份（1–12），詳細頁以 12 格月份圖呈現，當月加框
- 狀態徽章三態：本月當季 ✔ / 非產季 / 全年供應

### 3.3 價格判斷（核心功能）
- 輸入單價，單位三選一：**元/台斤**（預設，市場慣用）、**元/公斤**、**元/單位**（顆、把、條、串、片、尾、段、盒、支、隻、根、塊，依品項而定）
- 判斷結果以價牌風格大字呈現：
  - `俗！買起來`（螢光綠）：低於合理區間下緣
  - `價格合理`（螢光黃）：落在合理區間
  - `偏貴，再比比`（桃紅）：高於合理區間上緣；若非產季會附註「非產季貴很正常」
- 判斷邏輯（`fairKg()`）：
  ```
  有官方行情（prices.json 有該品項）：
    合理區間 = 近30天批發均價 × 加成(1.8) × [0.8, 1.15]
    （近期均價已反映季節，不再套產季係數）
  無官方行情（fallback 內建基準）：
    合理區間 = 內建批發區間中價 × 加成(1.8) × 產季係數 × [0.8, 1.15]
    產季係數：當季 0.85 / 非產季 1.15 / 全年供應 1.0
  retail:true 的品項（肉類、進口鮭魚）：
    w 值已是零售價，加成 = 1.0
  ```
- 台制單位換算：1 台斤 = 0.6 公斤
- 論個換算：單價 ÷ 該品項單位重量（kg）→ 元/公斤再比較。單位重量為「中等大小」估值，UI 有註明請使用者自行斟酌大小

### 3.4 行情更新（三層機制）
| 層級 | 觸發方式 | 行為 |
|---|---|---|
| L1 排程 | GitHub Actions cron（每日台北 06:00） | `scripts/update_prices.mjs` 抓近 30 天蔬果+漁產批發行情 → 聚合 → commit `prices.json` |
| L2 手動全站 | Actions「Run workflow」按鈕；或前端「🔄 更新行情」 | 重跑腳本 / 前端重新 fetch prices.json（cache-bust） |
| L3 手動單品項 | 詳細頁「查最新批發行情」按鈕 | 前端直接打農業部 API 抓近 7 天該品項均價（即時、不落地） |

- 前端載入時自動讀 `prices.json`；有資料 → header 顯示更新時間，品項參考價換用官方均價並標綠色「自動更新」來源標籤；讀不到 → 無縫退回內建基準，標「內建概略值」
- 肉類不接自動更新（見 5.3），前端隱藏 L3 按鈕並顯示說明文字

### 3.5 UI/UX 要求
- 手機優先（375px 起），單手可操作；品項詳細用 bottom sheet
- 視覺語言：菜市場螢光價牌（螢光綠/黃/桃紅 × 麥克筆黑 × 帆布綠底），標楷手寫感字體（LXGW WenKai TC）
- 離線容忍：內建基準資料在 HTML 內，收訊差時仍可用（僅無官方行情）

## 4. 資料源

| 資料 | 來源 | 端點 | 授權 |
|---|---|---|---|
| 蔬果批發行情 | 農業部農糧署（政府資料開放平臺資料集 #8066） | `GET https://data.moa.gov.tw/api/v1/AgriProductsTransType/` | 政府資料開放授權，免金鑰 |
| 漁產批發行情 | 農業部漁業署 | `GET https://data.moa.gov.tw/api/v1/AquaticTransData/` | 同上 |
| 對照網站 | 農產品批發市場交易行情站 | https://amis.afa.gov.tw | — |

- 共用參數：`Start_time`/`End_time`（民國年 `YYY.MM.DD`）、`Page`（分頁，回應含 `Next` 布林）；蔬果另支援 `CropName` 過濾
- 蔬果回傳欄位：`TransDate, CropCode, CropName, MarketName, Upper_Price, Middle_Price, Lower_Price, Avg_Price, Trans_Quantity`（元/公斤）
- **⚠️ 漁產端點的確切欄位名未經實測**，腳本與前端已寫防禦性 fallback（`Avg_Price / AvgPrice / 平均價`；`FishName / 魚貨名稱`），首次部署務必驗證（見 HANDOVER §1）

## 5. 資料模型

### 5.1 前端品項（`index.html` 內 `DB`）
```js
{
  n: "高麗菜",          // 顯示名（= prices.json 的 key）
  a: ["甘藍"],          // 別名（搜尋用）
  c: "葉菜",            // 分類
  w: [15, 25],          // 基準價區間 元/公斤（預設=批發價）
  retail: true,         // 選填。true = w 已是零售價，不加成、不接自動更新
  peak: [12,1,2,3,4],   // 盛產月；長度 12 = 全年供應
  pc: ["顆", 1.8],      // 選填。論個單位 [名稱, 一單位約幾公斤]
}
```

### 5.2 `prices.json`（排程產出）
```json
{
  "updatedAt": "ISO8601",
  "days": 30,
  "source": "data.moa.gov.tw",
  "items": { "高麗菜": { "kg": 21.3, "n": 412 } }
}
```
`kg`=近 N 天平均價（元/公斤），`n`=樣本筆數。key 必須等於前端 `DB[].n`。

### 5.3 官方品名對照（`scripts/update_prices.mjs` 的 `VEG_FRUIT`/`FISH`）
- 顯示名 → 官方品名關鍵字陣列，`includes()` 任一命中即納入平均
- 官方品名含品種後綴（例「甘藍 初秋」「鳳梨 金鑽鳳梨」），故用關鍵字部分比對
- **肉類刻意無對照**：官方拍賣資料為活體毛豬/家禽整體均價，與零售分切價（五花 vs 里肌價差大）無穩定換算關係，v1 維持內建零售基準

## 6. 已知限制與假設
1. 內建 `w` 基準區間為人工估的概略值（非統計結果），部署跑通 L1 後即被官方行情取代，僅剩 fallback 用途
2. 零售加成 1.5–2 倍（取 1.8）為傳統市場經驗值，未分品項校準
3. 單位重量為中等大小估值；同品項各攤差異可能達 ±50%（尤其葉菜的「一把」）
4. 批發均價為全台市場混合平均，未分市場/未加權交易量（改進見 backlog）
5. L3 即時查詢依賴 API 的 CORS 設定；若被擋，L1/L2 的 prices.json 路徑不受影響
6. 判斷不區分品質等級（批發資料的上/中/下價未使用，只用平均價）

## 7. Backlog（未實作的改進方向，依價值排序）
1. **交易量加權 + 分市場**：以 `Trans_Quantity` 加權，或只取使用者所在區域市場（北部：台北一/二、三重、板橋）
2. **產季自動判定**：以「該月歷史均價 vs 年均價」取代手工 peak 表（需抓 1–2 年歷史資料）
3. **歷史分位數判斷**：以近兩年價格分布的 P25/P75 取代「均價 ×0.8~1.15」，判斷更有統計意義
4. **PWA**：manifest + service worker，可加到主畫面、快取 prices.json 離線可用
5. 肉類接毛豬/家禽產地價做**趨勢提示**（漲跌箭頭），不做絕對價判斷
6. 使用者自訂校準：常買品項可微調單位重量與在地價格水準（注意：目前為靜態頁，無後端與帳號）
